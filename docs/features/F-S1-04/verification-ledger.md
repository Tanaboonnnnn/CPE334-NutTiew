## TDD RED → GREEN and LOOP 5 recovery evidence

1. **Database & Concurrency Suite (`apps/api/test/bookings.db.test.ts`):**
   - **RED / Initial run:** Ran `test/bookings.db.test.ts` against PostgreSQL 17.2; observed three failures:
     1. In `BOOK-30 / BOOK-31`, `beforeReconcile` paused while the failed `SERIALIZABLE` `PoolClient` was still checked out inside `finally`, and setting `Session.expiresAt = clock_timestamp() - interval '1 second'` without backdating `Session.createdAt` violated `Session_check` (`expiresAt > createdAt`).
     2. In `BOOK-17`, reusing `authCustomerLow` after `BOOK-02` had already booked a `+60m` Slot caused `CUSTOMER_OVERLAP` (`409`) before reaching the post-wait `Q05` (`422`) check.
     3. In `BOOK-19 / BDF-23`, an uncommitted `Booking` `INSERT` on `rogueClient` automatically acquired `FOR KEY SHARE` on `User(customerId)` via `booking_customer_fk`, blocking the adapter at Step 3 (`User` `FOR UPDATE`) before `beforeInsert` ran.
   - **GREEN fix:**
     1. Updated `apps/api/src/bookings.ts` to release the rolled-back `SERIALIZABLE` `PoolClient` (`client.release(); released = true;`) immediately before invoking `beforeReconcile` and opening the fresh `READ COMMITTED` reconciliation connection, matching `transaction-spec.md` §6.2 step 1 ("release its User/Slot/Session locks and connection").
     2. Isolated `BOOK-17` and `BOOK-19 / BDF-23` with dedicated Customer/Tutor fixtures, backdated `createdAt` alongside `expiresAt` in the `BOOK-30` expired-Session test fixture, and structured `BOOK-19 / BDF-23` into two explicit parts: Part 1 proving `booking_customer_fk` `FOR KEY SHARE` serializes uncommitted direct-SQL writers at the Step 3 `User` `FOR UPDATE` lock before `T_elig`, and Part 2 forcing a post-`T_elig` `booked_customer_no_overlap` GiST index wait that crosses the 60-minute `Q05` cutoff and verifying that our adapter aborts attempt `0` and retries attempt `1` with a fresh `T_elig` (`422 BOOKING_NOT_ELIGIBLE`).
     3. Re-ran `test/bookings.db.test.ts`: **14/14 PASS**.
2. **Playwright E2E Suite (`e2e/booking.spec.ts`):**
   - **RED / CI Run `#42507573357`:** `Unit / types / build` and `PostgreSQL 18 / Auth / Slot / Race A` passed in GitHub Actions CI, while `Microsoft Edge / Auth / Tutor UI E2E` failed on `e2e/booking.spec.ts:244` (`BOOK-28 / BOOK-29`) at `signIn()` (`expect(page.getByText('เข้าสู่ระบบแล้ว')).toBeVisible()`).    - **GREEN fix:** In `BOOK-28`, submitted the login form directly without asserting transient `'เข้าสู่ระบบแล้ว'` visibility before the expected post-CSRF binding-mismatch invalidation, then asserted `meAfterCsrfCount >= 1` and return to the login screen (`เข้าสู่ระบบ`).
