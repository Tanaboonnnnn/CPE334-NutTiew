# F-S1-01 — Authentication API Contract (Part E)

> **Proposed E-0.1, not implemented or approved.** Review with [Feature SDS](specification.md), [UI](ui-spec.md), [data](data-spec.md) and [STS](tests.md). Same-origin `/api/v1` follows System SDS §6. Endpoint shape, throttling and CSRF are OD-005 engineering decisions requiring peer approval **before code**.

## Shared transport and payload

- JSON UTF-8, strict allowlisted inputs, bounded body/email/password sizes; response `Cache-Control: no-store`; browser credentials sent via same-origin cookie automatically. No role or owner parameters accepted as authority.
- Success identity allowlist: `{ "user": { "id": "<UUID>", "role": "Customer" | "Tutor" } }`; never expose password hash, session ID, digest, token or other Customer/Tutor data. Email is excluded pending explicit approved UI need.
- Error envelope: `{ "error": { "code": "CODE", "message": "Generic safe description" }, "requestId": "<opaque id>" }`. No SQL errors, stack traces, raw credentials, account enumeration or private IDs.

| Method / path | Request / session check | Success | Proposed errors / privacy |
|---|---|---|---|
| `POST /api/v1/auth/login` | `{ "email": string, "password": string }` only; check same-origin `Origin`, active User and Argon2id hash | 200 identity DTO; `Set-Cookie` only after PostgreSQL Session insert commits | 400 `INVALID_INPUT`; uniform 401 `LOGIN_FAILED` for wrong, unknown and inactive; 403 `ORIGIN_DENIED`; approved 429 throttling; safe 503 on DB failure; no auth cookie on failure |
| `GET /api/v1/auth/me` | Live session cookie; read-only | 200 identity DTO derived from persisted User/Session | 401 `UNAUTHENTICATED` on missing, expired, revoked or inactive; no private payload |
| `GET /api/v1/auth/csrf` | Live cookie plus same-origin request; token never stored in browser localStorage | 200 `{ "csrfToken": "<opaque per-session value>" }` and `no-store` | 401 if no session; 403 for invalid cross-origin; lifetime/representation **OD-005** |
| `POST /api/v1/auth/logout` | Live cookie, allowed Origin and valid `X-CSRF-Token`; no other request fields | 204 empty body after **transactional current-session revocation commit**, expire presented cookie | 401 if session invalid; 403 `CSRF_DENIED` if invalid/missing Origin/CSRF; 503 DB failure **without falsely clearing live session or reporting success** |

## Cookie, authorization and replay contract

Production cookie is `nuttiew_session` with `HttpOnly; Secure; SameSite=Lax; Path=/`, no Domain; max age cannot exceed approved Session expiry. **Proposed 8-hour TTL is not yet approved (OD-005).** Only localhost HTTP may set `Secure=false` with distinct `nuttiew_session_dev`; never do so for remote HTTP. The server generates 32 bytes with a CSPRNG and stores only its SHA-256 digest (not the raw cookie) in DB. Every protected request checks active User plus unexpired, nonrevoked Session against server time. Logout must be **replay resistant**: manually restoring old cookie still returns 401; other independent sessions stay live.

**OD-005 candidate origin/CSRF decision (approval still required):** Do **not** require an `Origin` header on read-only `GET /api/v1/auth/csrf`, because same-origin browser GET may omit it. This GET requires a valid live cookie and same-origin/no-credentialed-CORS deployment; when `Sec-Fetch-Site` exists and equals `cross-site`, reject 403. **Stable derived CSRF lifecycle:** on login store a **32-byte random `Session.csrfNonce` (nonsecret)**, not a one-way hash of an unavailable raw CSRF token. A separately managed **256-bit-minimum `AUTH_CSRF_HMAC_KEY`** derives the response `base64url(HMAC-SHA256(key, 'NutTiew-CSRF-v1' || 0x00 || Session UUID bytes || csrfNonce))`. Repeated GET requests for a live Session derive the **same token without changing DB state**; both tabs and in-flight requests keep working. Server reconstructs the expected MAC from presented Session, rejects malformed header, and **constant-time compares** decoded `X-CSRF-Token` to the expected MAC on unsafe operations. A's token cannot authorize B even for the same User; expired/revoked Sessions fail first. CSRF token valid until session expiry/revocation or an explicitly reviewed key rotation. No raw token in DB/logs/browser persistent storage, and `Cache-Control: no-store` for GET; session-issued nonce and production key management/rotation are specified in [Data](data-spec.md) and [SDS](specification.md). **Part F blocked until peer approval.**

For `POST /auth/login`, `POST /auth/logout` and other unsafe cookie-mutating methods: compare `Origin` (scheme, host, port) to a **configured canonical web origin**, never to untrusted `Host` or forwarded headers. If `Origin` is present but foreign/malformed/`null`, **403** even if `Referer` appears local. If `Origin` is absent, permit **only** a syntactically valid `Referer` with matching canonical origin and `Sec-Fetch-Site` not `cross-site`; with neither header or forged/cross-site metadata, **403**. Any explicit `Sec-Fetch-Site: cross-site` also denies. Logout additionally requires `X-CSRF-Token` bound to the current Session before revocation. No credentialed cross-origin CORS. Approver: **@Tanaboonnnnn on OD-005-C before Part F**; see [SDS decision sheet](specification.md) and [AUTH-13/17](tests.md).

**Proposed reviewable input/rate limit defaults (not approved):** login body **<=4 KiB**, only `email` and `password`; trimmed lowercased email length **3–254 code points**, validated as email syntax; password **1–128 UTF-8 bytes** and unmodified, never trimmed. 400 invalid shape; 413 oversized; same generic 401 `LOGIN_FAILED` for unknown/wrong/inactive, using a dummy password hash verification for unknown user where appropriate. **Selected PostgreSQL atomic fixed-window limiter:** every accepted request first reserves one slot from both account and trusted-IP 15-minute buckets in a committed, row-locked transaction; account quota **5 total attempts/15min** (not failed-only; deliberate, reviewer-controlled change), IP quota **20 total/15min**. Counter keys are domain-separated **keyed HMAC** of canonical account email and trusted IP, never raw or trivially guessed email hashes; exceeding either returns identical safe **429 RATE_LIMITED** and consumes no reservation. Parallel API instances share DB row locks; no transaction held during Argon2, DB outage fails closed (sanitized 503), next fixed UTC 15-minute window resets naturally. Only explicitly allowlisted proxy addresses may supply client IP. This is a **DoS/availability tradeoff**, and OD-005-D/E require human approval before code; no silent in-memory-only limiter. See [Data atomic protocol](data-spec.md) and STS AUTH-20/22.
