## Shared transport and payload

- JSON UTF-8, strict allowlisted inputs, bounded body/email/password sizes; response `Cache-Control: no-store`; browser credentials sent via same-origin cookie automatically. No role or owner parameters accepted as authority.
- Success identity allowlist: `{ "user": { "id": "<UUID>", "role": "Customer" | "Tutor" } }`; never expose password hash, session ID, digest, token or other Customer/Tutor data. Email is excluded pending explicit approved UI need.
- Error envelope: `{ "error": { "code": "CODE", "message": "Generic safe description" }, "requestId": "<opaque id>" }`. No SQL errors, stack traces, raw credentials, account enumeration or private IDs.

| Method / path | Request / session check | Success | Proposed errors / privacy |
|---|---|---|---|
| `POST /api/v1/auth/login` | `{ "email": string, "password": string }` only; check same-origin `Origin`, active User and Argon2id hash | 200 identity DTO; `Set-Cookie` only after PostgreSQL Session insert commits | 400 `INVALID_INPUT`; uniform 401 `LOGIN_FAILED` for wrong, unknown and inactive; 403 `ORIGIN_DENIED`; approved 429 throttling; safe 503 on DB failure; no auth cookie on failure |
| `GET /api/v1/auth/me` | Live session cookie; read-only | 200 identity DTO derived from persisted User/Session | 401 `UNAUTHENTICATED` on missing, expired, revoked or inactive; no private payload |
| `GET /api/v1/auth/csrf` | Live cookie plus same-origin request; token never stored in browser localStorage | 200 `{ "csrfToken": "<opaque per-session value>" }` and `no-store` | 401 if no session; 403 for invalid cross-origin; lifetime/representation **OD-005** |
| `POST /api/v1/auth/logout` | Live cookie, allowed Origin and valid `X-CSRF-Token`; no other request fields | 204 empty body after **transactional current-session revocation commit**, expire presented cookie | 401 if session invalid; 403 `CSRF_DENIED` if invalid/missing Origin/CSRF; 503 DB failure **without falsely clearing live session or reporting success** |

## Cookie, authorization and replay contract

Production cookie is `nuttiew_session` with `HttpOnly; Secure; SameSite=Lax; Path=/`, no Domain; max age cannot exceed Session expiry. **OD-005-A 8-hour absolute TTL and OD-005-B current-session-only logout are APPROVED decisions (PR #25 comment #6624817784); implementation and tests are NOT RUN.** Only localhost HTTP may set `Secure=false` with distinct `nuttiew_session_dev`; never do so for remote HTTP. The server generates 32 bytes with a CSPRNG and stores only its SHA-256 digest (not the raw cookie) in DB. Every protected request checks active User plus unexpired, nonrevoked Session against server time. Logout must be **replay resistant**: manually restoring old cookie still returns 401; other independent sessions stay live.

**OD-005-C Origin/CSRF decision APPROVED by @Tanaboonnnnn in PR #25 comment #6624817784; implementation/tests NOT RUN:** Do **not** require an `Origin` header on read-only `GET /api/v1/auth/csrf`, because same-origin browser GET may omit it. This GET requires a valid live cookie and same-origin/no-credentialed-CORS deployment; when `Sec-Fetch-Site` exists and equals `cross-site`, reject 403. **Stable derived CSRF lifecycle:** on login store a **32-byte random `Session.csrfNonce` (nonsecret)**, not a one-way hash of an unavailable raw CSRF token. A separately managed **256-bit-minimum `AUTH_CSRF_HMAC_KEY`** derives the response `base64url(HMAC-SHA256(key, 'NutTiew-CSRF-v1' || 0x00 || Session UUID bytes || csrfNonce))`. Repeated GET requests for a live Session derive the **same token without changing DB state**; both tabs and in-flight requests keep working. Server reconstructs the expected MAC from presented Session, rejects malformed header, and **constant-time compares** decoded `X-CSRF-Token` to the expected MAC on unsafe operations. A's token cannot authorize B even for the same User; expired/revoked Sessions fail first. CSRF token valid until session expiry/revocation or an explicitly reviewed key rotation. No raw token in DB/logs/browser persistent storage, and `Cache-Control: no-store` for GET; session-issued nonce and production key management/rotation are specified in [Data](data-spec.md) and [SDS](specification.md). **Part E OD-005-D was approved by @Tanaboonnnnn (PR #25 comment #6625521193) and the approved Part E was merged into `sprint1`; Part F implementation and test acceptance are reviewed separately.**

For `POST /auth/login`, `POST /auth/logout` and other unsafe cookie-mutating methods: compare `Origin` (scheme, host, port) to a **configured canonical web origin**, never to untrusted `Host` or forwarded headers. If `Origin` is present but foreign/malformed/`null`, **403** even if `Referer` appears local. If `Origin` is absent, permit **only** a syntactically valid `Referer` with matching canonical origin and `Sec-Fetch-Site` not `cross-site`; with neither header or forged/cross-site metadata, **403**. Any explicit `Sec-Fetch-Site: cross-site` also denies. Logout additionally requires `X-CSRF-Token` bound to the current Session before revocation. No credentialed cross-origin CORS. **OD-005-C decision approved**, browser/security execution remains pending Part F; see [SDS decision sheet](specification.md) and [AUTH-13/17](tests.md).

**Login input contract (OD-005-E APPROVED in PR #25 Conversation comment 6624817784):** body **<=4 KiB**, only `email` and `password`; trimmed lowercased email **3–254 code points** with email syntax validation; password **1–128 UTF-8 bytes**, unchanged and never trimmed. Malformed shape 400, oversized body 413; identical 401 `LOGIN_FAILED` for unknown, wrong and inactive credentials with dummy Argon2 verification for unknown identity to reduce enumeration.

**Reviewer-requested OD-005-D rate-limit policy (APPROVED design, PR #25 comment #6625521193; Part F implementation evidence separate):** PostgreSQL 15-minute fixed UTC windows, two HMAC-keyed buckets: **5 FAILED credential verifications/account/15min**, with successful login **not counted as a failure**, and **20 TOTAL login attempts/trusted IP/15min**, including successful and failed requests. To avoid a race, a short admission transaction locks both rows in a stable order; rejects on `account.failed + account.inFlight >= 5` or `ip.attempts >= 20` with indistinguishable **429 `RATE_LIMITED`**; otherwise increments **IP total attempts** and reserves **account in-flight permit** and commits before Argon2. After credential verification, a separate short row-locked transaction releases the same permit and increments account **failed** only for wrong/unknown/inactive credentials. The Session and success 200/Set-Cookie must not be issued until that final transaction successfully commits and permits were settled; DB failure returns sanitized 503, no auth cookie. Untrusted proxy headers never choose the IP. A successful result spends one IP request but zero account failure quota. Reservation lease expiry and fixed-window rollover are defined in [Data atomic protocol](data-spec.md); AUTH-20/22 prove failed-only counters and concurrent upper bounds. **OD-005-D design approval was explicitly granted in PR #25 comment #6625521193; Part F evidence, including AUTH-20/22, still requires independent review.**
